## 工程类 · 用户调用（9）

- ask-matt — 路由器，根据当前局面帮你挑该跑哪个 skill。

- grill-with-docs — 访谈式追问同时构建领域模型，写入 CONTEXT.md / ADR。

- triage — 用状态机推进 issue 的分诊流程（new → triaged → …）。

- improve-codebase-architecture — 扫代码库找"加深机会"，输出 HTML 报告（含前后对比图）。

- setup-matt-pocock-skills — 一次性把这些 skill 装到指定仓库的引导脚本。

- to-spec — 把当前对话压成一份对外可发布的 spec。

- to-tickets — 把计划拆成带依赖边的 tracer-bullet 票据（垂直切片）。

- implement —拿到 spec/票据后，驱动 TDD + code-review 闭环落地。

- wayfinder — 给大型多 session 工程画一张"决策票据地图"。

---

## 工程类 · 模型自调用（9）

- prototype — 写一次性原型（单 HTML 文件或多 UI 变体）。

- diagnosing-bugs — 难 bug / 回归的纪律化诊断（Phase 1 先建 red-capable 反馈环）。

- research — 后台调研一手来源，输出带引用的 Markdown。

- tdd — 红绿重构循环，测试只在确认过的 seam 处写。

- domain-modeling — 打磨项目领域模型，更新 glossary / ADR。

- codebase-design — 设计深度、可测模块的共享纪律（"深模块、窄接口"）。

- code-review — 双轴 (Standards + Spec) 并行 sub-agent 的代码评审。

- resolving-merge-conflicts — 按意图逐 hunk 解 merge / rebase 冲突。

- wizard — 生成 bash 向导脚本，处理只能由人类完成的步骤。

---

## 生产力 · 用户调用（5）

- grill-me — 不停追问直到每个设计分支都被你拍板。

- handoff — 把当前对话压成给下一个 agent 的 handoff 文档。

- teach — 跨多 session 在有状态工作区里教一项技能。

- to-questionnaire — 把答不出的决策改成 Markdown 问卷让你填。

- wait-what — 用 CONTEXT.md 术语把被误读的消息用大白话重述。

---

## 生产力 · 模型自调用（2）

- grilling — grill-\* / triage 背后共用的"反复访谈"原语。

- writing-for-agents — 写给 agent 消费的文档时的写作指南（命名、口吻、抽象层）。
